# Intent：说清问题，而不是方案

**Intent** 是在 Specrails 中开始一项工作的方式。你不必先写方案，而是写下 **Intent**：问题是什么、想要什么结果、如何判断它奏效了、影响谁和什么、有哪些限制，以及目前还没有人知道的事。Specrails 会据此推导出 spec，你审阅 spec，而不是自己去写。（Intent 是原来 Flow 的新名称，并保留 Flow 的全部能力。）

## Intent 的构成

一个 Intent 有六个部分，其中没有“方案”这一项：

| 部分 | 写什么 |
| --- | --- |
| **问题** | 今天哪里不对、对谁、什么时候会造成困扰 |
| **期望结果** | 问题解决后什么成立，可附带一个假设 |
| **如何判断** | 可观察的信号；它们会成为验收标准 |
| **影响谁和什么** | 人、界面或系统 |
| **约束** | 任何方案都必须遵守的限制 |
| **待解决的问题** | 目前没人知道的事；智能体会去调查，而不是猜测 |

如果你直接写了一个方案（“加一个 Redis 缓存”），Intent 会把它的目的（“API 在 200 毫秒内响应”）保留为期望结果。你的方案若是硬性要求，就成为约束；若只是众多选项之一，就成为待解决的问题。Intent 只保存在 Specrails 中，不会发送到 Jira。

## Intent 从哪里来

- **在任务中。** 当你描述一项工作时，智能体会像分析师一样询问用户、限制，以及如何判断成功，然后显示一张 **Intent** 卡片，列出各个部分；若请求有歧义，还会给出两种理解。点击一种理解，或用自己的话回答。
- **在添加 spec 中。** **Intent** 是第一个模式，默认打开。描述问题，点击 **生成 Intent 和规格**，然后审阅两者。参见[添加 spec 的各个模式](/docs/specs-specs-and-the-backlog)。

每个处理该 spec 的智能体都会先收到 Intent，把它当作“为什么”和“要什么结果”的依据，而不是“怎么做”的依据。Rail 交付带有 Intent 的 spec 时，会把它写成 OpenSpec 变更中的 `intent.md`，因此它和代码一起保存在 Git 中。

## 探索或委派

确定后的 Intent 提供两条地位相同的路径。没有推荐项，由你选择。

- **探索**：在隔离的 Intent 会话中与智能体一起构建。结果满意后，由 rail 根据你们构建的内容推导出 spec。适合形态尚不清晰的情况：探索性或偏视觉的工作。
- **委派**：由智能体根据 Intent 撰写 spec，你审阅后，由 rail 使用 [Implement](/docs/pipeline-rails-and-jobs) 构建。适合你想要的东西已经很明确的情况。

## 开始 Intent 会话

选择 **探索**。会弹出确认：Specrails 创建一个隔离的 worktree，智能体可以在其中写代码，主分支不受影响。点击 **开始 Intent**。看板上会出现带有你的 Intent 的占位 spec，标签为 **Intent 中**；点击它即可回到任务。你也可以在看板或 spec 详情中，通过 **在 Intent 中开始** 把任何现有 spec 放进 Intent。

## 构建过程中始终由你掌控

输入框上方的栏会显示 worktree 分支、已更改的文件及增删行数，以及提供商实际计费的费用（绝不是估算）。

- **查看更改** 列出每个已更改的文件及其状态和 +/−。
- **暂停 Intent** 会停止智能体，并保留 worktree 和 spec。之后任务会提供 **恢复 Intent**，即使重启应用也一样。
- **丢弃** 在确认后删除 worktree、其分支和占位 spec。原本就存在的 spec 会原样恢复。
- **随时打断**：智能体工作时直接输入，你的消息会打断当前步骤。

Intent 只在自己的 worktree 内写入；在 Intent 之外，任务保持只读。一个任务同一时间只有一个 Intent。

## 交给 Rail

对结果满意后，点击 **交给 Rail**。该行显示 **可以变成 PR 了**，rail、引擎、模型和投入程度已为你选好。需要的话可以调整，然后点击 **启动**，或点击 **暂不** 返回。若达到评审上限或预算，该行会说明，并且不会启动任何内容。

Rail 会根据你构建的内容推导出 spec 和 OpenSpec 变更，验证并评审它们，归档变更，并像任何运行一样交付。交付卡片会出现在任务中，[评审包](/docs/missions-review-and-delivery)会显示推导出的 spec 解释了多少变更。如果运行因技术原因失败，工作会原封不动地回到 Intent。

## Jira 只在交付时介入

处于 Intent 期间或丢弃它时，不会有任何内容进入 Jira。在连接了 [Jira](/docs/integrations-jira-integration) 的项目中，只有当交付进入评审时才会创建 issue，此时它已包含推导出的 spec。

## 使用要求

Intent 要求 Desktop 内置的 Specrails Core 支持它。如果 **开始 Intent** 不可用，卡片会列出缺少的内容；请在 **Desktop 设置 → 更新 → Specrails Core** 中更新 Specrails Core。Intent 的费用会在 Analytics 中作为独立的 **Intent** 类别显示。
