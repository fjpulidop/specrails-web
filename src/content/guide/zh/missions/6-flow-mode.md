# Flow：先构建，后写 spec

**新功能。** 在还不确定自己到底想要什么时，Flow 让你和智能体一起构建可运行的代码。你在任务对话中与智能体交流，它在隔离的 worktree 中编写并运行真实代码，事先不需要任何 spec。结果满意时点击 **就是这样**，轨道会推导出 spec，并像往常一样交付这项工作。

## Flow 用于探索，Implement 用于委派

如果你已经能描述清楚变更（规则、验收标准、API 或数据模型），请使用 [Implement](/docs/pipeline-rails-and-jobs)：先确定 spec，再交给轨道执行。

如果形态还不清楚（探索性或视觉性的需求，或是想在投入之前先试试的想法），请使用 Flow。你们一起构建，在过程中发现结果，spec 则根据构建出的内容来编写。

## 从任务中开始 Flow

你不需要点名要求 Flow。当你描述探索性的需求（"我想试试……"、"我不知道它该长什么样"）时，任务中会出现一张卡片，提供两条路径：**Flow**，现在一起构建；**Spec + Implement**，先确定 spec。卡片会标出推荐路径，并用一句话说明原因。另一条路径始终一键可选；如果你选择它或点击 **暂不**，智能体不会再坚持。

选择 Flow 后会出现确认：Specrails 会创建一个隔离的 worktree，智能体可以在其中写代码，你的主分支不会被改动。点击 **开始 Flow**。看板上会出现一个带有 **Flow 中** 标签的临时 spec；点击即可回到任务。

## 构建过程中始终由你掌控

对话的外观会改变，输入框上方会出现 Flow 工具栏。它显示 worktree 的分支、带有增删行数的已更改文件，以及 Flow 的实际费用（以提供商计费为准，绝不显示估算值）。

- **查看更改** 列出每个更改的文件及其状态和 +/−。
- **暂停** 会停止智能体，并保留 worktree 和 spec。之后任务中会提供 **恢复 Flow**，即使应用重启后也一样。
- **丢弃** 在确认后删除 worktree、其分支和临时 spec。
- **随时打断**：智能体工作时你也可以输入，你的消息会打断当前步骤。发送按钮会变成闪电图标，智能体会立即根据新信息继续。

Flow 只在自己的 worktree 中写入；在 Flow 之外，任务仍然是只读的。每个任务同一时间只能有一个 Flow。

## 点击"就是这样"

对结果满意后，点击 **就是这样**。Flow 工具栏会消失，出现熟悉的轨道启动卡片，已预选 **Flow → Spec** 循环并为你选好一条空闲轨道。如有需要可调整引擎、模型或推理强度，然后点击 **启动**。如果已达到审查上限或预算，卡片会说明原因且不会启动。**暂不** 会让你回到 Flow。

Flow → Spec 循环会根据你构建的内容推导出 Specrails spec 和 OpenSpec change，进行验证和审查，归档该 change，并像其他运行一样交付。交付卡片会出现在任务中，[审查材料](/docs/missions-review-and-delivery) 会显示推导出的 spec 解释了变更的哪些部分。

## Jira 只在交付时介入

在 Flow 期间或丢弃 Flow 时，Jira 不会收到任何内容。对于已连接 [Jira](/docs/integrations-jira-integration) 的项目，只有当交付进入审查时才会创建 issue，内容已包含完整的推导 spec，并直接进入映射为审查的状态。

## 使用要求

Flow 从引入它的 Specrails Desktop 版本开始提供，并要求 Desktop 内置的 Specrails Core 支持 Flow。如果 **开始 Flow** 不可用，卡片会列出缺少的内容；请在 **Desktop 设置 → 更新 → Specrails Core** 中更新 Specrails Core。Flow 的费用会在 Analytics 中作为独立的 **Flow** 类别显示。
