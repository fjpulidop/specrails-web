# Elige un loop y sigue su rail

Un loop define el proceso; un rail es el carril de ejecución; un job o run registra lo ocurrido. Las misiones pueden lanzarlos por ti y Board ofrece los mismos controles directamente.

## Elige el proceso adecuado

| Loop | Para qué sirve |
| --- | --- |
| Implement | Una spec acordada, con arquitectura, implementación y revisión |
| Batch Implement | Un conjunto coordinado de specs y dependencias |
| SDD Quick | Un recorrido SDD más corto para un cambio acotado |
| Freestyle | Una tarea flexible con un resultado explícito |
| Personalizado | Tus pasos de IA, shell y decisión |

Selecciona proveedor, modelo compatible y repositorios antes de empezar. Comprueba requisitos y capacidad: un rail reservado o en cola no demuestra que el modelo haya empezado.

## Interpreta el resultado mediante evidencias

Sigue el paso activo, la verificación y los motivos de fallo. Un test de base correcto no demuestra que exista la función: la revisión debe comprobar el comportamiento pedido. Los límites de iteración y tiempo detienen un loop que no puede completar el trabajo.

Una implementación terminada produce una [entrega revisable](/docs/missions-review-and-delivery). No automatiza por sí sola todas las integraciones o publicaciones.
