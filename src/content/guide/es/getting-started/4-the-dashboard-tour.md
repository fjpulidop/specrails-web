# Oriéntate en el espacio de trabajo

El modo misión es el punto de partida para hablar con el agente y seguir el trabajo. El modo Board ofrece una vista organizativa del mismo backlog del proyecto.

## Empieza por la misión

Selecciona el proyecto, abre una misión y describe el resultado en el compositor. Los controles de proveedor, modelo y permisos se aplican a las operaciones del agente; ajústalos a la tarea. Usa referencias para identificar una spec, un archivo o un repositorio con precisión.

El espacio reúne conversación, tarjetas de entrega, archivos, Git, navegador y terminal. Abre los paneles que necesites: leer código no requiere editarlo y consultar un proceso no requiere otra sesión de terminal.

## Usa Board para organizar trabajo

Board agrupa las specs por estado y prioridad. Los rails permiten elegir un loop e inspeccionar sus pasos. Cambia de vista para planificar varias specs o repartir trabajo independiente entre rails; vuelve a la misión para seguir dirigiendo el trabajo desde la conversación.

En la aplicación nativa, las [ventanas de misión separadas](/docs/missions-mission-windows) permiten mantener visibles tareas independientes. El agente continúa en el backend local compartido.

## Usa el pie y organiza las conversaciones

El pie muestra el uso local de las suscripciones de Claude y Codex. Pasa el ratón o enfócalo para consultar cada ventana, el tiempo hasta su reinicio y la última actualización correcta. El uso incluye actividad fuera de Specrails; un valor no disponible no es cero. El selector nativo Mantener despierto evita la suspensión por inactividad mientras está activo y vuelve a Off al reiniciar la app.

Usa Split View para comparar misiones distintas; una conversación ya visible no ofrece una división redundante. Los controles de las sidebars están en la barra de título nativa, y Docs, Analytics, Companion y Settings comparten la fila inferior.
