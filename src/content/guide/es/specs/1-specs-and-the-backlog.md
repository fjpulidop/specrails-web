# Las specs y el backlog compartido

Una spec es el acuerdo duradero de un cambio. Aporta a la implementación algo más que un mensaje: un resultado, unos límites y evidencias que puedas revisar.

## Haz útil el contrato

Describe el problema, el comportamiento esperado, los criterios de aceptación, las restricciones y los repositorios afectados. Incluye ejemplos y casos de fallo. Indica lo que queda fuera para distinguir el trabajo necesario de las ideas relacionadas.

«Premium» describe la profundidad del contrato y su creación, no una garantía de que el modelo lo implemente bien. Revisa las suposiciones generadas y haz comprobable cada criterio importante.

## Conserva un único backlog

Misiones y Board comparten el backlog del proyecto. Una spec con varios repositorios sigue siendo una spec con una selección explícita; no se copia a otros backlogs. Sin esa selección se utiliza el repositorio principal.

Usa [Quick](/docs/specs-add-spec-quick-mode) para una petición clara, [Explore](/docs/specs-add-spec-explore-mode) para resolver dudas o Raw para escribir el contrato. Revisa el borrador antes de guardar y lanzar.
