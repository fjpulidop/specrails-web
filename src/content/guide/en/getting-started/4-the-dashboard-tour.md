# Find your way around the workspace

Mission mode is the starting point for talking to the agent and following the work. Board mode gives the same project backlog an organizational view.

## Start with the mission

Select the project, open a mission and use the composer to describe an outcome. The provider, model and permission controls apply to agent operations; choose settings appropriate to the task. Use references to identify a spec, file or repository precisely.

The workspace brings together conversation, delivery cards, files, Git, browser and terminal. Open only the panels you need: reading code does not require an editor, and inspecting a process does not require another terminal session.

## Use Board when organizing work

Board groups specs by status and priority. Rails let you choose a loop and inspect an implementation's steps. Switch views to plan several specs or manage a batch; returning to the mission keeps the conversation as your place to direct the work.

In the native app, [separate mission windows](/docs/missions-mission-windows) let you keep independent tasks visible. The agent remains in the shared local backend.
