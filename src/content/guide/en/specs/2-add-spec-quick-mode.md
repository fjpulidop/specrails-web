# Create a spec with Quick or Raw

Quick turns a focused request into a draft you can inspect. Raw lets you enter the specification directly without an authoring model call.

## Start with an observable outcome

Open Add Spec in the active project. In Quick, describe who needs the change, what should happen and how you will check it. Add relevant constraints and choose the target repositories. Submit the request and wait for the draft.

Check its title, description, acceptance criteria and repository scope. Correct invented assumptions before saving. Generation errors leave an action to retry; they are not successful saves.

## Separate creation from execution

Saving adds the spec to the shared backlog. Launching an implementation is a separate action that selects the loop and execution settings. The saved scope becomes the reference for the run.

If the request has unresolved design choices, continue in [Explore](/docs/specs-add-spec-explore-mode). If you already have an agreed contract, paste it into Raw and review the same fields.
