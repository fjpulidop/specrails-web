# Your first mission

Begin with the outcome you want, then let the mission gather enough project context to propose a precise change.

## Give the agent a useful brief

For example: “Add password recovery to this product. Check the API and frontend, propose the acceptance criteria, and wait for the spec before implementing.” Mention constraints, existing behavior and how you will judge the result.

Select the intended project. Use **#** to reference a spec and **@** for project context such as files. Spec suggestions take priority, and references stay at the insertion point. Check the repository label when filenames repeat across repos. Attach relevant screenshots or files; do not include credentials.

## From conversation to work

Review the proposed spec and its repository scope. When it is ready, ask the agent to run the suitable loop. Watch the live steps and delivery cards. A model saying “done” is not a substitute for recorded verification and your delivery decision.

While the agent runs, Send queues another message by default. Use the pending message's explicit steering action to deliver a correction without stopping the invocation. **Stop** is a separate action.
