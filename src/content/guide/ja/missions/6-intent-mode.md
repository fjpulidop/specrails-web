# Intent: 解決策ではなく、課題を伝える

**Intent** は、Specrails で作業を始める方法です。解決策を書く代わりに、**Intent** を書きます。課題は何か、どんな結果を目指すか、うまくいったとどう確かめるか、誰と何に影響するか、制約は何か、まだ誰も知らないことは何か。Specrails はそこから spec を導き、あなたは spec を書く代わりにレビューします。（Intent はこれまで Flow と呼ばれていたものの新しい名前で、Flow の機能はすべて引き継いでいます。）

## Intent の中身

Intent は 6 つの部分からなり、解決策のための欄はありません。

| 部分 | 書く内容 |
| --- | --- |
| **課題** | 今何が問題か、誰にとってか、いつ困るか |
| **目指す結果** | 解決したときに成り立つこと。仮説は任意 |
| **達成の確かめ方** | 観察できる兆候。受け入れ条件になります |
| **影響を受ける人と対象** | 人、画面、システム |
| **制約** | どの解決策も守るべき制限 |
| **未解決の問い** | まだ誰も知らないこと。エージェントは推測せずに調べます |

解決策を書いた場合（「Redis キャッシュを追加する」）、Intent はその目的（「API が 200 ms 未満で応答する」）を結果として残します。あなたの解決策は、必須なら制約に、選択肢の一つなら未解決の問いになります。Intent は Specrails の中に留まり、Jira には送られません。

## Intent の出どころ

- **ミッションで。** 作業を説明すると、エージェントがユーザー、制約、うまくいったかの確かめ方をインタビューし、すべての部分を並べた **Intent** カードを表示します。依頼があいまいなときは 2 通りの解釈も示します。解釈をクリックするか、自分の言葉で答えてください。
- **スペックの追加で。** **Intent** は最初のモードで、デフォルトで開きます。課題を説明して **Intent とスペックを生成** を押し、両方をレビューします。[スペック追加のモード](/docs/specs-specs-and-the-backlog)を参照してください。

スペックに取り組むすべてのエージェントは、まず Intent を受け取ります。Intent は「なぜ」と「どんな結果か」の拠り所であり、「どうやるか」の拠り所ではありません。レールが Intent 付きのスペックをデリバリーすると、Intent は OpenSpec の変更に `intent.md` として書き込まれ、コードと並んで Git に残ります。

## 探索するか、任せるか

確定した Intent には、対等な 2 つの進め方があります。どちらも推奨ではなく、選ぶのはあなたです。

- **探索する**: 隔離された Intent セッションで、エージェントと一緒に作ります。結果が良ければ、作ったものからレールが spec を導きます。形がまだ見えていないとき、つまり探索的・視覚的な作業に向いています。
- **委任する**: エージェントが Intent から spec を書きます。あなたがレビューし、レールが [Implement](/docs/pipeline-rails-and-jobs) で作ります。やりたいことがすでに明確なときに向いています。

## Intent セッションを始める

**探索する** を選びます。確認が開きます。Specrails はエージェントがコードを書ける隔離された worktree を作り、メインブランチには触れません。**Intent を開始** を押します。あなたの Intent を持つ仮の spec が **Intent 中** ラベル付きでボードに表示されます。クリックするとミッションに戻れます。既存のスペックも、ボードやスペック詳細の **Intent で開始** から Intent で始められます。

## 作っている間も主導権はあなたに

コンポーザーの上のバーに、worktree のブランチ、変更されたファイルと追加・削除の行数、プロバイダーが請求した実際のコスト（推定値ではありません）が表示されます。

- **変更を表示** は、変更された各ファイルを状態と +/− 付きで一覧にします。
- **Intent を一時停止** はエージェントを止め、worktree と spec を残します。その後ミッションに **Intent を再開** が表示されます。アプリを再起動しても同じです。
- **破棄** は確認のうえ、worktree、そのブランチ、仮の spec を削除します。もともと存在していた spec は元の状態に戻ります。
- **いつでも割り込めます**: エージェントの作業中に書き込むと、メッセージが現在のステップに割り込みます。

Intent は自分の worktree の中にだけ書き込みます。Intent の外では、ミッションは読み取り専用です。ミッションに同時に存在できる Intent は 1 つです。

## 引き渡す

結果に満足したら **引き渡す** を押します。行には **PR にする準備ができました** と表示され、レール、エンジン、モデル、effort はすでに選ばれています。必要なら調整して **起動** を押すか、**まだ** で戻ります。レビュー上限や予算に達していれば、その旨が表示され、何も起動しません。

レールは作ったものから spec と OpenSpec の変更を導き、検証とレビューを行い、変更をアーカイブして、通常の実行と同じようにデリバリーします。デリバリーカードがミッションに表示され、[レビューパケット](/docs/missions-review-and-delivery)で導かれた spec が変更のどれだけを説明しているかを確認できます。技術的な理由で実行が失敗した場合、作業はそのまま Intent に戻ります。

## Jira はデリバリー時だけ

Intent 中や破棄したときは、Jira には何も届きません。[Jira](/docs/integrations-jira-integration) に接続されたプロジェクトでは、デリバリーがレビューに達したときに初めて、導かれた spec を含む完成した状態で issue が作られます。

## 必要条件

Intent には、Desktop に内蔵された Specrails Core が対応している必要があります。**Intent を開始** が無効な場合は、不足しているものがカードに表示されます。**Desktop 設定 → 更新 → Specrails Core** から Specrails Core を更新してください。Intent のコストは Analytics で独立したサーフェス **Intent** として表示されます。
