# 成果物をレビューして受け入れる

実装は、確認すべき変更と検証結果を作成します。既存のテストが成功しても、要求された機能の完成を証明するものではありません。

## 操作を区別する

ローカル統合は、確認された統合先ブランチへ変更を適用します。チェックアウトは作業ブランチをリポジトリのローカルフォルダーへ移す操作で、スペックの受け入れとは異なります。PR の前にリポジトリ、対象ブランチ、差分を確認してください。worktree は隔離された Git の作業フォルダーであり、GitHub 上の作業環境ではありません。

## 部分的な結果を保つ

複数リポジトリでは、明示的な変更なしの結果も含めて各成果物を確認します。統合はリポジトリ間で不可分な処理ではありません。他の操作が失敗しても、受け入れ済みの結果は記録に残ります。

競合やベース変更が起きた場合は、ローカル変更を保ち、エラーを読んで未完了の操作だけを再試行します。カードを消すために worktree を削除しないでください。修正依頼は固定済みの範囲と前回の成果物のコンテキストを引き継ぎます。
